# Agent Note: Open Fish Harness Pack runtime

Status: implemented

English | [中文](2026-08-20-openfish-harness-pack-runtime.zh.md)

## Problem

Open Fish was a native shell over one DSH runtime. Adding Codex, Pi, Oh My Pi, or a future Harness directly to the shell would make every provider a product-specific branch, require users to preinstall tools, and misrepresent private runtime internals as a common graph.

## Decision

Open Fish selects a Harness per session. A Harness is the execution system that turns intent, context, and a model into controlled, observable, resumable action; it owns the agent loop, tools, permissions, session semantics, and provider-facing configuration. Harness Pack v0 owns identity, protocol, distribution, publisher metadata, availability, and an evidence-backed Architecture Manifest. Graphs declare `opaque`, `observable`, or `composable`; opaque Packs expose exactly one honest runtime boundary, while observable and composable Packs must declare one connected evidenced control flow. There is no cosmetic node minimum: the view shows every evidenced responsibility the Pack or Driver can support and does not invent private internals. Only Pack-declared editable nodes with a typed Driver binding may change execution. Generic catalog discovery and session code do not branch on provider ids.

DSH remains the built-in native path. Codex uses a dedicated Driver for the official `codex app-server` protocol, preserving live ChatGPT/API account state, models and reasoning levels, thread resume/delete/fork, tool calls, approvals, and native events. Generic ACP installs each package version through bundled Node/npm, pinned Bun, bundled uv, or a checksummed bounded platform archive and launches the exact managed snapshot. It persists ACP remote identity, maps the lossless native update stream into the common Session surface, and bridges standard approval, cancel, image, file, and terminal callbacks without taking ownership of the remote agent loop. The official ACP Registry and generated OpenFish community catalog populate discovery at startup. Built-ins and configured user Packs override every collision, while official ACP entries override community entries. Community entries remain unverified and follow the same exact-version admission rules. The curated Oh My Pi Pack uses its published ACP command through pinned Bun because it is not yet listed by the Registry.

`session.create` accepts `harnessId` and an optional client-generated `sessionId`. A client prepares exactly one blank durable identity before the first turn, persists only that id plus the selected Harness in its private per-Host projection cache, and adopts the same task after a lost response or app restart. Existing sessions reject a conflicting Harness. Every cold API entry restores the Harness recorded in `harness/selected`; it never silently resumes external history through DSH. An untouched draft may be discarded locally, but a started task is never deleted through the draft path. Codex maps discard to provider `thread/delete`; generic ACP stops the abandoned process because ACP defines no provider-side delete primitive.

Agent Presets remain DSH-only. Codex models, reasoning levels, and account identity come from live app-server state; ACP models and standard options come from each live ACP session. Model/configuration mutations serialize per session and always reconcile the authoritative Driver state, including when the initiating UI request is cancelled after the mutation reaches the wire. Editable composable nodes may declare `acpSessionOptions`; the generic Driver applies those defaults to a new session and rejects values the Harness does not advertise. The Host persists a shared default, installs, non-secret authentication preference, active version, and rollback snapshots. The macOS landing flow requires one default choice and installs the selected Pack when needed; macOS and iOS settings update that same Host-owned default, while each blank task may choose another Harness before its first turn. Native selection uses a Progressive Lens: Simple explains who the Harness is for and how it signs in, Architecture explains evidenced responsibilities and their current runtime state, and the Mac Manifest Editor creates, imports, validates, preflights, and exports Packs. iPhone provides the same Simple and Architecture understanding plus a read-only Builder handoff; publishing and credential-bearing edits stay on the authoritative Mac Host. Publication is a credential-free manifest contribution to the generated community catalog.

Each session without a Workspace receives its own Host-owned `$DSH_HOME/openfish/no-project/<sessionId>` cwd. It is grouped as “No Project” on both clients and never inherits Desktop, a launcher cwd, or another no-project task's files.

## Alternatives considered

- **Hard-code DSH, Codex, and OMP adapters.** This optimizes the first roster but does not prove that a fourth ACP Harness can arrive without a shell rebuild.
- **Treat Harness as a model provider.** Harness owns the agent loop, tools, approval protocol, and session semantics; a model route cannot represent that ownership.
- **Promise one editable graph for every process.** A black-box CLI exposes neither stable nodes nor safe mutation semantics. Opaque execution plus lossless native events is truthful; composability must be declared by its Pack.
- **Require users to install every CLI.** That defeats the integrated-product requirement. npm ACP Packs are installed on demand inside the Open Fish runtime path.

## Verification

Manifest, lifecycle, Driver conformance, ACP integration, API carrier, native client, pairing, sandbox, release, and privacy checks form one release gate. They cover Pack admission, arbitrary Registry projection, opaque/evidenced/composable graphs, exact-version installation, bounded archive extraction, third-party Driver registration, lifecycle-script consent, atomic update/rollback, authoritative model/config mutation, exact prepared-draft recovery, No Project isolation, lossless native events, real capability gating, voice lifecycle failure, pairing proof/revocation, and Mac/iPhone cold resume. Live DSH, Codex, and OMP traces and a synthetic unknown ACP fixture are recorded separately so passing contract tests are never presented as provider certification.

## Consequences

Any compatible ACP Registry entry can appear, install, and run without shell code changes. Unknown Registry agents remain one opaque boundary until stronger evidence exists. DSH, official Codex app-server, and curated Oh My Pi use source-derived manifests with meaningful responsibilities; Open Fish UI, the operating system, and the model provider remain outside the Harness boundary. A new protocol implements Driver API v1 and may arrive through an exact, user-consented public Driver Bundle without a native app release. Driver code is staged with lifecycle scripts off, structurally admitted, process-isolated, capability-negotiated, and still treated as third-party executable code rather than a safe data-only Pack. Graph editing is enabled only for Pack-declared composable nodes with operational Driver bindings; browser login remains Harness-owned, API keys remain in the Host credential service, and conversations never claim portability across Harnesses.
