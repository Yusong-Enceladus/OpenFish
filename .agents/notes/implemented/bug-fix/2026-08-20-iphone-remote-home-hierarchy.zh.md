# Agent Note: iPhone 远程首页层级

Status: implemented

[English](2026-08-20-iphone-remote-home-hierarchy.md) | 中文

## Problem

iPhone target 没有生成启动屏幕，因此现代设备可能会在带上下留黑的兼容画布中显示应用。远程首页还会在始终展开的工作区分组中展示全部任务，导致用户尚未选择项目，小屏幕就已被任务占满。

## Decision

仅支持 iPhone 的 target 会生成原生启动屏幕、要求全屏并声明手机方向，使 SwiftUI 获得完整设备画布，而不是进入 iPad 兼容窗口。远程首页复现 ChatGPT Remote 的几何尺寸：44 点高的自定义顶部栏、32 点高的已连接电脑胶囊、44 点高的扁平任务行，以及常驻底部的 40 点搜索与操作栏。自定义栏避免 iOS 26 导航和 Liquid Glass 样式把控件放大到明显超过 Remote 参照。DSH 工作区仍作为 36 点高的可折叠一等分组，因为它是用户的项目导航单位。包含最近更新任务的工作区会首先展开；搜索会临时显示所有折叠分组中的匹配任务。

Session 行会缩进到工作区标题之下，不再和工作区共用同一条左边界。所有任务集合都会过滤 Host 明确标记为空白的 Session，包括未归类和已归档集合，因此占位 Session 不会反复显示为 `New task`，空的 `Other tasks` 分组也会消失。记录了 `cwd` 并不等于具备 Git 元数据，因此客户端不会据此推断或绘制 Git/worktree 标志；只有 Host 协议今后提供明确 Git 数据时才能显示这类标志。

任务详情使用一条连续对话流，不再把消息拆成装饰性卡片。用户、assistant、reasoning、notice 和网页结果正文会通过原生 CommonMark／GFM 渲染器展示，而不是直接交给 SwiftUI `Text`；标题、列表、表格、链接、引用、行内代码、fenced code 和任务列表会保留原本结构，尚未完成的流式 Markdown 也会以可读形式降级。持久图片块通过带认证的 `session.attachment` 边界加载，不暴露 Host 路径或远程图片 URL。

工具活动保持紧凑且可展开。折叠摘要来自 presenter 标题和关键参数字段，而不是序列化参数 JSON。展开内容会根据 Host 所有的 render-intent card 分流：terminal 命令和输出使用可复制的等宽区块并显示退出状态；diff 使用有颜色的修改前后行；read 保留行号和语言提示；search 保留分组匹配或路径及截断恢复信息；web 保留 Markdown 答案和来源；generic 降级会格式化结构化输入／输出并保留每一个 content block。权限请求使用靠近底部的操作卡，输入框固定在底部。这些呈现选择会保留任务菜单中额外的 DSH 控制，但不让它们侵入主要阅读路径。

这套层级仍然只是 Host 工作区和会话数据的展示方式。配对、同步、任务选择和对话执行继续由现有组件负责，网络行为保持不变。

## Alternatives considered

**保留普通且始终展开的 `Section` 分组。** 原生分组所需状态更少，但会继续形成没有边界的任务长墙，导致用户难以在手机上选择项目。

**保留系统 `List`、分组外观和导航栏搜索。** 这些控件能以较少代码提供滑动操作和系统样式，但组合后会让每个项目看起来像一张很宽的设置卡，并把主要操作移出 Remote 任务界面。自定义滚动层级仍使用带语义的 SwiftUI 控件、动态字体、上下文菜单和有标签的操作。

**完全复制 ChatGPT Remote 的时间分组。** `Pinned` 和 `Today` 适合官方产品的全局任务流，但用它们替代 DSH 工作区会移除客户端需要的项目级折叠。实现借用其信息密度和导航模式，同时继续展示工作区归属。

## Consequences

首页会填满当前 iPhone 显示区域，用户可以先浏览项目，再展开任务历史。展开状态刻意不做持久化；重新打开应用时，仍优先显示包含最新工作的工作区。搜索优先于折叠状态，因此匹配任务不会被隐藏。任何首页集合都不能再选择空白占位任务，工作区数量也只统计已经开始的任务。归档任务从滑动操作改为上下文菜单，以单手发现性换取扁平 Remote 布局；展开归档分组后仍可直接恢复任务。
